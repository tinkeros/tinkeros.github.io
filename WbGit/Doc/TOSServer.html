TOSServer


TOSServer is tos_server.py written in HolyC. It answers TOSClient on a COM port, 
so one TinkerOS machine can give another one files, its clipboard, URL fetches 
and a HolyC command line, with no Linux machine in between. The client side is 
unchanged: ProbeComm, Fget, Fput, Dget, Dput, Dsync, Hdir, ClipGet, ClipPut, 
HExec, HGetOS, URLGet all work as they do against tos_server.py.

Starting a server

TOSServer(1);   Serial: a UART (a null-modem cable to the other machine, or a 
virtual machine's serial port). Any COM port works.

With the network loaded (#include "::/Demo/Net/Start";), the TCP COM ports of 
CommTCP:

TOSServerTcp(7777);     Listen on TCP port 7777, like tos_server.py --mode 
server. The client machine connects with AddTcpCommCli("<this machine's 
ip>",7777);.

TOSServerTcpCli("192.168.1.20",7777);   Connect out, like tos_server.py --mode 
client. The client machine listens first with AddTcpCommSrv(7777);.

On the client machine, ProbeComm; then finds the server, and every TOSClient 
call works.

Arguments

All four take, after the port: dir="~/TOSXfr", the transfer directory (made if 
missing; the client's names are relative to it, and names that leave it are 
refused), exec=FALSE and bg=TRUE.

exec    TRUE lets the client's HExec run HolyC on this machine, in the server's 
task, and get back what it printed. Off by default: a client could run anything 
in ring 0. Over TCP that means anyone who can reach the port.

bg      TRUE runs the server in a background task (any number of them, one per 
COM port). FALSE runs it in the current task, printing each request, until Esc.

Managing servers

TOSServerRep;   What each server has done: requests, files in and out, bytes, 
errors, the last request.
TOSServerStop;  Stop all of them, or TOSServerStop(com); one. A port that TOSSer
verTcp/TOSServerTcpCli made is closed too.

Background servers log each request to the Adam log (AdamLog).

Differences from tos_server.py

  
  * HExec runs HolyC, not a shell command, and only with exec=TRUE.
  * HGetOS answers TinkerOS.
  * URLs: http:// only (no https), and only with the network loaded. URLGetTextS
  tr gets the page with its tags, scripts and styles removed.
  * The socket commands (create_connection, send, recv) also need the network. r
  ecv waits at most 200 ms for data.
  * A file sent to Foo.HC when Foo.HC.Z exists replaces Foo.HC.Z, and Fget("Foo.
  HC") finds Foo.HC.Z, as on the client side. Other names keep their .Z 
  (compressed on disk).
  * Dsync and Dget compare MD5 sums of the uncompressed contents on both sides.

Notes

  
  * ProbeComm skips a COM port this machine's own TOSServer runs on, so one 
  machine can be server and client at once (on two ports wired together).
  * The network part is in TOSSrvNet, which Demo/Net/Load.HC includes. Including 
  TOSServer.HC again afterwards drops it (include TOSSrvNet again).
  * Serial speed is 115200 baud, about 11 KB/s. A TCP port is several times 
  faster.
